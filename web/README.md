# Group trip planner prototype (web)

Static Next.js prototype. Demo data only: no backend, no API keys, no paid services. Everything is saved in the browser's `localStorage`.

## Run it

From the repository root, the portable Node install lives in `../.tools`. If you already have Node 20 or newer, skip the PATH line.

```bash
export PATH="$PWD/../.tools/node-v26.13.1-darwin-arm64/bin:$PATH"
npm install
npm run dev        # http://localhost:3000
```

## Checks

| Command | What it does |
|---|---|
| `npm run typecheck` | TypeScript in strict mode |
| `npm run lint` | ESLint |
| `npm test` | Unit tests (Vitest) for the logic in `lib/` |
| `npm run build` | Static export to `out/` |
| `npm run test:e2e` | Browser suites against the static build (run `npm run build` first) |
| `npm run check` | All of the above, in order |
| `npm run preview` | Serve `out/` at http://localhost:4173 |

To test the GitHub Pages build, set `NEXT_PUBLIC_BASE_PATH=/Travel-App-Prototype` for both `npm run build` and `npm run test:e2e`. See `../docs/HOSTING_PLAN.md`.

Browser suites use puppeteer-core with a project-local `chrome-headless-shell` in `../.tools/browsers`. To install it once: `cd ../.tools/browsers && npx @puppeteer/browsers install chrome-headless-shell@stable`. Set `CHROME_PATH` to use another Chrome.

## Product name

The product is called **Joliday**. The name lives in one place: `lib/brand.ts`. Change `BRAND_NAME`, or set `NEXT_PUBLIC_BRAND_NAME=Travely` in `.env.local`, then rebuild. Nothing else in the code is name-specific.

## Demo trips

Four trips ship with the prototype (`lib/demo/`). Chicago is the default. Each trip is saved separately, so progress in one never touches another. **Reset demo** (Profile or More) restores all of them and removes trips you created.

| Trip | Highlights it demonstrates |
|---|---|
| Chicago Birthday Weekend | The protocol's seed trip: varied votes, a nearly full boat tour, a ride-share pair |
| Aspen Ski Weekend | A limited-seat lesson, a full cabin, a $0 activity |
| Lisbon Bachelorette Weekend | Two overlapping Saturday plans, overnight flights |
| Austin Live Music Weekend | Five flights landing close together, tight budget, free activities |

## Adding another demo trip

1. Copy `lib/demo/aspen.ts`, change the data (it is built with the helpers in `lib/demo/builders.ts`).
2. Register it in `lib/demo/index.ts`.
3. `npm test` checks that the new trip is internally consistent.

## Costs are optional

Each trip has a "Track costs" switch (Profile > Trip settings, organizer only, and in the create flow). Turn it off for planning with no money: prices, shares, totals, payment labels and budgets disappear, and activities never need a cost. Saved prices are kept. Code: `costsOn()` in `lib/selectors.ts`, `showCosts` on the trip.

## Calendar

`/trip/calendar` shows the trip as month grids (one per month the trip touches) with a schedule for the chosen day: timed plans on an hour grid (overlaps sit side by side), plans with no time, and who is flying in or out. The Overview has a "Trip at a glance" strip that opens a day. "Add confirmed plans to my calendar" and the per-activity "Add to my calendar" button download an `.ics` file for Apple, Google or Outlook calendars. Logic and tests: `lib/calendar.ts`, `tests/unit/calendar.test.ts`.

## Look and feel

Colors are tokens in `app/globals.css` (`@theme`): cool white canvas, deep indigo ink, one indigo accent (`brand`). Display font is Plus Jakarta Sans, body is Figtree (`app/layout.tsx`).
